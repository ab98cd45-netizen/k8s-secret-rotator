# 🛡️ Kubernetes Secret Rotator

Инструмент для автоматической ротации секретов (паролей, API-ключей) в кластере Kubernetes. Разработан для автоматизации рутины и повышения безопасности инфраструктуры.

## 🎯 Какую проблему решает
Хранение статичных паролей — это риск для безопасности. Регулярная смена секретов вручную — это рутинная работа, которая приводит к человеческим ошибкам. Этот проект автоматизирует ротацию паролей по расписанию без простоя сервисов.

## 🏗 Архитектура
Проект состоит из трех основных компонентов:
1. **Victim (Жертва)**: Тестовое приложение на Python, имитирующее работу сервиса. Оно читает пароль из переменной окружения, которую ему передает Kubernetes.
2. **Rotator (Ротатор)**: Python-скрипт, запускаемый как `CronJob`. Он генерирует новый пароль, обращается к Kubernetes API для обновления `Secret`, а затем делает `rollout restart` для `Deployment` (жертвы), чтобы приложение подхватило новый пароль.
3. **Kubernetes API**: Связующее звено. Ротатор использует `ServiceAccount` с правами (RBAC), позволяющими ему изменять только нужные секреты и деплойменты.

## 🛠 Стек технологий
* **Язык:** Python 3.11 (библиотеки: `kubernetes`, `secrets`)
* **Оркестрация:** Kubernetes (Minikube для локального запуска)
* **Контейнеризация:** Docker
* **Автоматизация:** Bash (`setup.sh`)

## 🔐 Безопасность
Особое внимание уделено безопасности самого ротатора. Применен принцип **Least Privilege**:
* Создан отдельный `ServiceAccount` (`rotator-sa`).
* Через `Role` и `RoleBinding` ему разрешены **только** методы `get` и `patch` к секретам и деплойментам. Он не может создавать новые поды или удалять неймспейсы.

## 🚀 Быстрый старт (Developer Experience)

Для развертывания достаточно одной команды. Убедитесь, что у вас установлены `Docker`, `Minikube` и `kubectl`.

```bash
# Сделайте скрипт исполняемым и запустите
chmod +x setup.sh
./setup.sh
```

Скрипт автоматически:

- Проверит наличие зависимостей и запустит Minikube (если нужно).

- Соберет Docker-образы для Victim и Rotator.

- Загрузит образы в локальный кластер Minikube.

- Применит все манифесты (Secret, Deployment, RBAC, CronJob).

## 🧪 Как проверить, что всё работает
Посмотрите пароль в секрете (до ротации):

```bash
kubectl get secret db-secret -o jsonpath='{.data.BD_PASSWORD}' | base64 -d
```
Проверьте логи "жертвы" (она прочитала этот пароль при старте):

```bash
kubectl logs -l app=victim
```
Запустите ротацию вручную (не дожидаясь расписания CronJob):

```bash
kubectl create job --from=cronjob/rotator-cronjob manual-rotation-1
```
Подождите 10 секунд и проверьте секрет снова. Вы увидите новый пароль! Если посмотреть логи victim, она перезапустилась и использует новый пароль.

## 🧹 Очистка ресурсов
Чтобы удалить все созданные ресурсы и остановить Minikube:

```bash
kubectl delete -f manifests/
minikube stop
```
